# T105 全站球员双语姓名展示设计规格

**状态：** 用户已确认，2026-09-26
**任务：** [T105](../../../CURRENT.md#t105-全站球员英文主名中文辅名统一in_progress)

## 目标

让整个网站对球员身份采用一致的展示层级：英文名是主要名称，已有中文名是次要辅助信息；不再由不同页面各自决定只显示英文、只显示中文或把两者挤在同一行。

## 已核实的现状

- canonical `Player` 已有英文 `name` 和可空 `localized_name`；比赛 REST DTO 已可提供两者。
- 球员目录、资料和部分结果组件已经显示双语，但首页、比分/走势、部分比赛组件和市场区存在只显示短英文名或单一名称的情况。
- 前端 `PlayerViewModel` 当前会丢弃 `PlayerDto.localized_name`。
- P3 的 `_match_facts` 当前以 `localized_name or name` 填充 `player_names`，因此中文名被塞入主名字段；Opportunity、Market、Paper 和 Pulse 共用该语义。

## 用户确认的规则

1. 所有结构化球员身份位置统一显示英文主名在上、中文辅名在下；中文名不存在或为空时只显示英文。
2. 覆盖 Home 比赛卡/赛果/市场脉搏和助手球员候选，Match 比分/统计/PBP/走势/球员卡，Markets 的全部市场/机会/Paper，以及 Players 的排名/搜索/资料/当前比赛/历史对手。
3. 空间紧凑的比分、走势或事件标签可保留现有英文短名，但也按英文主、中文辅排列；不改变比赛数据和版面信息优先级。
4. AI 自然语言回答保持自然表达；只对结构化球员卡片/字段应用此展示规则。
5. 已映射的市场球员使用 canonical 英文名和已有中文名。无法可靠映射的 market-only outcome 保留供应商原始名称，不猜球员身份或生成中文翻译。
6. 不改变球员解析/别名、翻译生成、供应商、市场匹配、模型、机会筛选、paper 生命周期或任何比赛事实。

## API 与数据规则

- P3 `player_names` 表示顺序与 `player_ids` 对应的主要（canonical English）名称；未匹配的市场行继续使用其供应商 outcome label。
- P3 `OpportunityDto`、`MarketSummaryDto`、`PaperPositionDto`、`PulseRowDto` 增加顺序对应的可空 `player_localized_names` 二元组。未知/未映射球员的中文名为 `null`。
- 匹配市场按内部 player ID 关联名称；不得依靠字符串猜测中文名。该字段仅影响响应展示，不参与决策或交易逻辑。
- 无数据库 migration、额外供应商请求、LLM 调用或新依赖。

## 验收条件

- 共享前端姓名组件在全部上述结构化展示位置呈现英文主名和可用的中文辅名；null/空中文名不会形成空行或占位文案。
- P3 REST 序列化、前端类型、严格解码、view model 和组件保留同一球员顺序；市场 outcome 顺序不变。
- 未映射市场仍展示供应商名称且没有虚构中文名；决策/Paper 输出与改动前一致。
- 回归测试覆盖有中文、无中文、P3 双语字段、旧响应缺少新字段和未映射市场。桌面/移动端关键页面检查布局无截断/遮挡。
- 不读取或输出根 `.env`；保留用户已有的未提交代码和文件。
