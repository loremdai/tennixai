# T106 逐分得分者未知状态展示规格

**状态：** 已核实，2026-09-26
**任务：** [T106](../../../CURRENT.md)

## 问题与根因

- API-Tennis 的逐分数据提供分数变化和逐分序号，没有一个可直接映射的逐分 winner 字段。
- 后端仅在前后比分能确定只有一方得分时填充 `winner_player_id`。比分相同或变化矛盾时，保留 `null` 并记录 `winner_indeterminate`；这符合不猜数据的领域规则。
- Match 逐分时间线把每个 `null` 都显示为“胜者待定”，使已发生但无法确认的记录看起来像尚未发生，还造成大量重复文案。

## 目标与边界

让用户清楚区分“已确认的得分者”和“现有记录无法确认的得分者”，不伪造比赛事实。

- 已确认胜者仍显示其球员姓名，其他球员姓名与中英文展示不变。
- null 或无法对应到本场两名球员的胜者行显示紧凑的中性横线；为辅助技术提供“得分者未能确认”的可访问文本。
- 只在整段时间线顶部提示一次：“部分逐分记录无法确认得分者”。
- 比分、逐分顺序、局/盘分组、关键分标记及更新时间行为保持不变。
- 不更改 API-Tennis 映射、canonical winner、动量计算、REST/SSE、数据库、供应商调用或模型逻辑；不根据发球者或其他未定义语义猜测得分者。

## 验收条件

1. 多个 `winner_player_id=null` 或无法对应到本场球员的记录不再显示重复“胜者待定”，每条仅显示中性占位符。
2. 至多出现一条时间线级说明，明确部分得分者无法确认。
3. 已知胜者仍显示正确球员姓名；记录分数与顺序不变。
4. 新回归先证明旧界面错误，再证明修复；MatchPointsTimeline 定向 Vitest 与 TypeScript 检查通过。
5. 不读取/输出根 `.env`，不触发 API/LLM/Polymarket 请求，不重启当前运行服务；仅提交本任务明确列出的文件。
