# T116 — 市场页信息层级与扫读体验设计

**日期：** 2026-09-29

**状态：** 待用户审阅；本任务只交付设计，不授权实施

**页面：** 生产 `/markets`，桌面与手机

## 目标与依据

用户选择的首要目标是「信息更清晰、扫读更快」。普通网球用户进入市场页后，应先知道一场比赛是否有可读报价，再迅速比较双方价格、辨认报价是否仍有效；只有确实有模型判断时，才需要阅读模型数字。三视图与模拟边界继续遵循 [PROJECT.md](../../../PROJECT.md) 和 [消费者前端设计](./2026-09-24-tennixai-consumer-frontend-design.md)。

2026-09-29 对运行中的生产页做了只读检查：默认「机会」因模型未完成验证而为空；「全部市场」加载首批 50 / 2195 场，包含已结束、未匹配、报价过时与缺乏流动性的行。现有行将比赛名、双方报价、模型空值、价差/深度与状态放在五个等权列中；长名称在标题和报价区域被截断。筛选面板和大幅空态占用首屏，用户需要滚动后才能比较市场。这里的 50 / 2195 是当时的运行快照，不是页面固定文案或未来覆盖承诺。

## 方案选择

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 优化现有三视图（推荐）** | 保留深色与荧光绿视觉、现有路由和数据契约；重排首屏、筛选与三类列表行；用渐进披露容纳次要指标。 | 能解决主要扫读问题，改动集中在生产前端，现有状态语义可直接复用。 |
| B. 桌面市场数据表 + 手机卡片 | 桌面同时展示更多行，手机另做卡片布局。 | 跨视口维护两套信息顺序，长姓名与多种状态容易让表格过宽；本阶段没有必要。 |
| C. 全新发现式卡片墙 | 强调赛事图片、图表和大面积视觉卡。 | 视觉变化大，但同屏比赛数下降，报价不易横向比较，与「扫读更快」的目标相反。 |

采用 A。页面仍固定为「机会 / 全部市场 / 模拟记录」，默认进入「机会」。当模型未晋升时，不自动切换视图，也不生成机会；用紧凑空态解释原因并提供「查看全部市场」入口。

## 页面骨架

1. **页头：** 一行标题「比赛市场」、简短说明和「仅模拟」标识。保留一次明确的非真实交易说明，去掉重复的大块说明卡；不把供应商、内部阶段或模型版本写进产品文案。
2. **三视图导航：** 保留既有名称、URL `view` 状态与键盘左右键行为。当前视图高对比，手机只显示主标签；不加入没有可靠数据来源的计数角标。
3. **全局状态：** 页面级报价延迟提示缩成单行。它说明「部分报价更新较慢」；每个受影响行仍单独显示最后有效时间和状态。状态色始终配有文字。
4. **视图内容：** 标题、可用的结果计数或空态在筛选前后紧密排列。生产内容与冻结的 `?preview=p3` 原型分离；设计不要求重写预览基线。

## 三视图的内容优先级

### 机会

- 顶部先给**动作与目标球员**，其后给模型估算胜率、固定 `$10` 的可执行买入均价、模型与市场差距和更新时间。`WAIT` 才显示最高可接受买入价；无该值时不留空槽。
- `BUY / WAIT` 等动作只来自服务端真实 decision observation；页面不自行按两项概率计算 edge 或创建模拟意图。
- 模型未晋升、无覆盖比赛、决策流缺口、确实没有机会与加载失败分别沿用现有原因。空态缩至简短标题、原因和一个「查看全部市场」入口；不使用占满首屏的高空白面板。

### 全部市场

- 每行优先顺序：**比赛/赛事与阶段 → 双方真实胜出买入参考价 → 报价状态/最后有效时间 → 可用的次要指标**。目前五列等权的布局改为上述顺序。长比赛名不截成无法辨认的片段。
- 有真实模型估算和决策记录时，在次要区域清楚写明概率对应哪位球员，并显示真实动作与原因。没有模型输出时不保留一整列「—」；低级别、双打和未匹配市场不出现「未覆盖」「等待评估」等负向模型标签，只说明市场报价状态。
- 平均价差与最优档金额保留现有定义，只在有可信值时出现；两者都缺失时用报价状态解释，不以 `0` 或虚构数字补齐。`0%` 与空值必须可区分。
- 已匹配市场整行进入内部比赛页；未匹配市场保留非链接卡，不显示箭头或可点击悬停效果。`closed`、`stale`、`partial`、无流动性和不可用状态始终以文字说明。
- 顶部计数明确为「已加载 N / 全部 M 个市场」。筛选只作用于已加载页面时，可加「当前显示 K 个市场（已加载 N 个）」；不得把 K 写成全市场匹配总数。现有「加载更多」继续工作。

### 模拟记录

- 首先分「进行中」和「近期已结束」两组，开放持仓与待确认仍按现有优先级排列。每行先看比赛、方向与模拟状态，再看投入/份额、退出参考金额、模拟盈亏和更新时间。
- `entry_pending` 的计划投入不是已成交成本；`missed` 没有持仓；`exit_pending` 不暗示已退出；`settled` 与已退出各自保留真实状态。金额、成本、盈亏和状态继续直接取现有账本视图模型，不在前端重算成交或结算。
- 模拟说明保留在视图开头或结尾一次；行内只在值可能被误认作可提取资金时附简短限定。

## 状态和交互规则

| 情况 | 设计表现 | 用户下一步 |
|---|---|---|
| 机会为空且模型未晋升 | 紧凑说明「模型仍在验证中」；无假概率与假机会 | 查看全部市场报价 |
| 市场报价正常 | 双方各自的真实参考价、更新时间、真实状态 | 已映射时进入比赛详情 |
| 报价过时或流中断 | 保留最后有效价，行内标出「上次有效报价」与时间；页面上方简短汇总 | 等待刷新或看其他市场 |
| 只取得一侧报价/无流动性 | 缺侧显示 `—`，旁边写明 `partial` / 无流动性；不补互补价 | 查看已知一侧及状态 |
| 未匹配比赛 | 使用供应商提供的 outcome 名称与报价；整行不跳转 | 继续浏览市场 |
| 加载失败 | 若有最后可信行则保留并提示失败；没有行时显示重试 | 重试加载 |
| 筛选后为空 | 说明仅对已加载行生效，提供重置；如果还有更多页仍保留加载更多 | 减少条件或继续加载 |
| 模拟账本为空/待确认/已结算 | 各状态用现有账本事实与独立文案，不混作「尚未买入」或「已获利」 | 查看单场记录或稍后再看 |

## 视觉与无障碍

- 沿用全站深色、绿色强调、现有字体与共享组件；不用新字体、图标库、插画、图片源或动画依赖。重点数字使用等宽数字和足够的对比度；荧光绿只用于真实动作/重点，不把普通市场报价染成「机会」。
- 悬停只改变边框/背景，不让卡片上下移动；键盘焦点沿用明确的 ring。状态同时用文字、徽章和颜色表达。可点击整行在桌面/手机都有可识别反馈；未匹配行不伪装链接。
- 测试视口以 `1440×1000`、`390×844` 为主，补查 375、768、1024 px；不能横向溢出。移动触控目标至少 44 px。动态结果使用现有 `aria-live`，不在报价频繁变化时逐行打断屏幕阅读器。
