# T95 Match Field Integrity Matrix

Status: complete. Every canonical field below is traced through provider mapping, persistence/reducer, REST/SSE, and UI or explicitly marked unavailable/unknown. Confirmed defects have a named regression test and fix evidence.

Evidence: API-Tennis [REST documentation](https://api-tennis.com/documentation), [WebSocket documentation](https://api-tennis.com/documentation_websocket), sanitized fixtures under `backend/tests/fixtures/api_tennis/`, canonical models, repositories/reducer, response DTOs, and page consumers. REST and WebSocket docs show event identity/status, scheduled date/time, players, tournament, score rows, server, PBP and statistics; they do not document tie-break encoding, PBP flag value semantics, source-update timestamps, indoor/format, or the meaning of every omitted WebSocket field. Their examples show empty PBP/score/stat arrays and nullable round.

Shared path: API-Tennis DTO → `api_tennis.py` canonical mapper → `MatchSnapshot`; the realtime worker applies `reduce_live_snapshot`; `MatchSnapshotRepository` persists canonical match/player/tournament, score state, freshness, points, statistics, momentum and quality. REST `/matches/{id}` serializes `MatchSnapshot`; SSE `ready` serializes the same shape and `match_delta` carries reducer changes. Frontend mirrors it in `frontend/lib/api/types.ts`. Statuses: `verified`, `bug fixed`, or `unavailable / undocumented by provider contract`.

## Provider-only fields and explicit limits

The API-Tennis DTO accepts forward-compatible vendor fields, but the canonical layer intentionally does not pass them through. The official REST examples include `first_player_dp1_key` / `first_player_dp2_key` and second-side equivalents for doubles, tournament season/qualification fields, and statistic `stat_type`, `stat_won`, `stat_total`. WebSocket PBP game objects also include `serve_winner`, `serve_lost`, and a game-level `score`. These are not represented in the current single-player-per-side `Match` / point-level statistic model; no meaning is inferred from them. API-Tennis single/doubles classification is retained, but doubles partner identities are not independently modeled.

Other intentionally unmodeled fields include vendor logos/images and supplier external IDs in public output. External IDs remain inside the provider identity mapping. API-Tennis has no match-row indoor/format, player-country alpha-3, source event timestamp, or distinct tie-break flag in the documented REST/WS schema. Separate profile/standings calls can supply country/rank metadata; country values are mapped only through the explicit canonical country table.

### Unknown provider semantics (not guessed)

- Tie-break marker/score representation and whether 7-6 score rows encode tie-break points.
- Meaning and truth values of nullable `break_point` / `set_point` / `match_point` values (`First Play` is present in a sanitized fixture; official docs show null but do not define either null or non-null tokens). All remain `null`, never inferred as false/true.
- Whether omitted WebSocket arrays/fields mean “unchanged” or “cleared”; official docs say updates are pushed but do not define merge semantics. Reducer retention of sparse statistics is an explicit local policy: omitted metrics stay with their original time and become stale; newly received metrics refresh independently. Regression: `test_empty_statistics_update_retains_last_values_as_stale`, `test_sparse_statistics_update_refreshes_present_metric_only`.
- API-Tennis provides no source event/update timestamp; local `observed_at` / `as_of` are not substitutes and are labeled as local observation clocks.
